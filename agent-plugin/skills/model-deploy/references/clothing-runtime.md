# 衣装の通常再読み込み

com3d25-devbridge の専用ツールで、導入済みの衣装を現在の menu のまま再読み込みする。
ツールが事前確認（対象の一致・busy・参照先ファイルの存在・同名 menu の重複）と前後比較を行うため、`eval_csharp` で `SetProp` やファイルシステムを直接操作しない。

## 手順

1. **新しいファイルを認識させる**（mate / tex 等を新規に追加した場合だけ）: `refresh_mod_files` に正規の導入先 `directory`（`<gameDir>/Mod` 配下の絶対パス）と manifest の `files` 辞書（短いファイル名 → SHA-256）を渡す。全件のハッシュを照合してからゲームの Mod 検索一覧へ登録し、各ファイルの認識を確かめる。既存ファイルの上書きだけなら不要。
2. **対象を確定する**: `list_maids` と現在の装備から、ストック番号 `maidIndex`・`mpn`・TBody スロット `slot` を決める。表示中の番号とストック番号を混同しない。
3. **調べる**: `inspect_clothing` に `maidIndex` / `mpn` / `slot` を渡す。返った `maidId` と `menu`（一時装備があれば `temporaryMenu`）を控える。全 Renderer の Mesh・材質・テクスチャが前後比較の基準になる。
4. **再読み込み**: `reload_clothing` に同じ 3 項目と `expectedMaidId`・`expectedMenu`（現在有効な menu。一時装備があればそちら）を渡す。`timeoutMs` は省略時 10 秒（500〜30000）。menu 名・RID・スケール設定は書き換えず、一時装備は一時装備のまま再処理される。
5. **確かめる**: 返った `before` / `after` の Mesh ID・頂点数・subMesh 数・材質順・shader・テクスチャを出力検証と照合し、`screenshot` または `capture` で見た目を確認する。ツール結果と画像を作業フォルダーの検証記録に保存する。

## 結果の読み方

- `refresh_mod_files` の `status=registered` はファイル検索への登録で、通常ロードや表示確認の完了ではない。
- `reload_clothing` の `normalLoadCompleted=true` は、再読み込み要求の成功、busy の解消、対象装備と Mesh の存在、対象外 menu の保持を確認したことを示す。
- `visualVerified` / `geometryVerified` は常に false。Mesh ID・頂点数・材質枠数やテクスチャ寸法だけではファイル内容の完全一致を証明できない。画像だけの更新など、ID や寸法で判定できない変更は表示や画素で確認する。
- 追加した材質枠が読み込まれているか、内蔵材質だけ成功して menu の材質変更が失敗していないかを、ファイル存在・menu 命令・ログと合わせて確認する。

## 制限と落とし穴

- **同じフォルダーへの新規追加は、そのセッションで初回の登録時しか検索対象に入らない**（ゲームが登録済みフォルダーを再走査しないため）。2 回目以降に追加したファイルは `refresh_mod_files` の認識確認で失敗するので、ゲームの再起動が必要と報告する。既存ファイルの上書きはいつでも反映される。
- Mod 配下に同名の menu が複数あると、検索順を変えないよう登録を中止する。重複導入を先に解消する。
- 初回装備、別 menu への着替え、SceneEditor の単独モデル・Prefab・ステージはツールの対象外。
- ツールがエラーを返したら、同じ操作を自動で再送しない。ツールは失敗時に衣装やファイルを復元しないので、現在の状態とログを調べ、導入時の退避記録から復元を判断する。
- `meshIdsChanged=false` や見た目が古い場合は、再読み込みを繰り返す前に導入先の重複・検索順・menu 内容・対象名を調べる。複製 Mesh やライブ材質の直接変更で見た目を合わせて「通常ロード済み」と報告しない。
- カメラやポーズは検証に必要なときだけ変更し、先に復元用の状態を控える。
