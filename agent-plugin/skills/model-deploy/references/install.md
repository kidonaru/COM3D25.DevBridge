# manifest による導入

`scripts/install_manifest.py` は Python 3 の標準ライブラリだけを使う。ZIP の展開、モデルの生成、ゲームの操作は行わない。ネストした構成の MOD や Prefab は既存のプロジェクト用インストーラーを優先する。

対象は、同じフォルダーに置かれた model / mate / menu / tex と、以下の形式の manifest.json:

    {"files": {"item.model": "SHA-256の64桁文字列", "item.menu": "SHA-256の64桁文字列"}}

manifest の用意:

- 配布フォルダーに manifest.json があれば、それを使う
- 既に導入済みの MOD を入れ直す・照合するだけなら、導入先にある manifest.json を配布フォルダーへ写して使う。作り直すと manifest.json 自体のハッシュが変わり、「変更が必要」と誤って出る
- どちらにも無い場合だけ、配布ファイルの SHA-256 から作る

スクリプトの扱う範囲:

- 導入するもの: `files` に列挙されたバイナリ、manifest.json、存在すれば README.txt だけ。source にある他のファイルはコピーしない
- 検証レポート: manifest 自体と README のハッシュも含める
- **このスクリプトが検証しないこと**: バイナリ形式の正当性・参照関係・最新の編集結果との一致。別の出力検証で確認する

以下の `<skill>` はこのスキルのディレクトリ。

## 検査のみ

    python "<skill>/scripts/install_manifest.py" --source "<配布フォルダー>" --mod-root "<gameDir>/Mod" --destination "<既存の作者フォルダー>/<対象MODフォルダー>"

destination は絶対パスでもよい。相対パスは mod-root から解決する。検査ではファイルを書かず、導入予定と変更が必要な件数を JSON で返す。mod-root 直下を丸ごと導入先にはできない。manifest 内のパス・別拡張子・大文字小文字だけが異なる名前の重複を拒否する。

## 導入

同じ引数に以下を加える。

    --apply --backup "<作業フォルダー>/archive/<新しい退避名>" --report "<作業フォルダー>/reports/install.json"

スクリプトの処理順:

1. 全入力を検査する
2. 既存の対象ファイルを退避する
3. 導入前のハッシュが変わっていないことを確認する
4. コピーし、導入後のハッシュを照合する

指定の制約:

- backup は未作成の場所を指定する
- backup・report を Mod の中へ置かない
- 失敗後に同じ退避フォルダーを使って再実行しない

導入先にだけある無関係なファイルは保持される。部分失敗時は、failed 状態・コピー済みファイル・before/after ハッシュをレポートから確認できる。

権限が必要な導入先への `--apply` は、利用中のエージェントの許可手続きを経たシェルで実行する。スクリプトの引数は構造化した引数配列または正しく引用した固定パスで渡す。書き込み許可のないゲームパスを別の実行ツールで迂回しない。

成功レポートでも `normal_reload_confirmed` / `visual_checked` は false。衣装やアセットの再読み込みを別途行ったあと、その実機証拠を追記する。コピー成功を実機検証済みに変換しない。
